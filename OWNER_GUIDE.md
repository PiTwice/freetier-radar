# FreeTier Radar — руководство владельца

Этот документ — твоя единственная «должностная инструкция». Всё остальное делает система.

## Что это за бизнес (одним абзацем)

FreeTier Radar — контент/каталог-бизнес для разработчиков: сайт, который отвечает на массовый поисковый запрос «есть ли у X бесплатный тариф и в чём подвох». Ценность — проверенность данных (дата верификации + источники + ловушки) и «Кладбище free tier» как вирусный крючок. Деньги приходят не от продажи товара, а от аудитории: подписчики рассылки об изменениях тарифов → спонсорские слоты в рассылке и на сайте, донаты через GitHub Sponsors, позже — партнёрские программы dev-инструментов (честно помеченные и никогда не влияющие на рейтинг — это обещано в FAQ публично). Продукт доставляется автоматически: сайт отдаёт статические страницы, рассылку рассылает платформа.

## BUSINESS ENGINE

TRAFFIC — Google находит 22 SEO-страницы (главная + 21 страница инструмента с FAQ-разметкой) + всплески с Reddit/HN/dev.to → **автоматически после индексации**
VISITOR → сайт объясняет ценность за 5 секунд (hero + бейджи + ловушки) → **автоматически**
REGISTRATION → подписка на рассылку в 1 клик (Substack/Buttondown) → **автоматически**
ACTIVATION → первое же письмо об изменении тарифа доказывает ценность → **автоматически**
VALUE → человек избегает «сюрприза» (усыплённая БД, умерший free tier) → **автоматически**
PAYMENT → спонсор платит за слот; донаты через GitHub Sponsors → **автоматически (Stripe внутри платформ)**
DELIVERY → сайт + письмо, ничего не отправляется руками → **автоматически**
RETENTION → каждое изменение тарифа = повод для письма = удержание → **полуавтоматически (см. «еженедельный ритуал»)**
REFERRAL → «Кладбище» и алерты шарят в чатах/твиттере; кнопка Watch on GitHub → **автоматически**
RECURRING REVENUE → подписки спонсоров помесячно → **автоматически**

## Твой еженедельный ритуал (единственная регулярная работа)

Понедельник, после письма от GitHub:

1. Нет issue от radar-bot → ничего не делаешь. Всё.
2. Есть issue → открыл флагнутые pricing-страницы (5–15 мин), поправил tools.json, `python3 scripts/build.py`, commit+push.
3. Если изменение значимое (лимит урезан / free tier умер) → короткий выпуск рассылки из 3–5 предложений и пост в 1–2 места (r/webdev, твиттер/X, HN-комментарий в тему). Это твой маркетинг — 15 минут, и именно он растит подписчиков.

## Запуск с 0 € — по шагам (однократно, ~2 часа)

1. **GitHub** (10 мин): создай публичный репозиторий `freetier-radar`, залей все файлы. В `data/tools.json` замени `USERNAME` в `base_url` и `repo_url` на свой логин, запусти `python3 scripts/build.py`, закоммить.
2. **Хостинг** (5 мин): Settings → Pages → Deploy from branch → main / root. Сайт живой.
3. **Мониторинг** (0 мин): workflow уже в `.github/workflows/watch.yml` — заработает сам. Проверь вкладку Actions, запусти вручную первый раз (Run workflow) — он создаст базовые снапшоты.
4. **Рассылка** (20 мин): заведи бесплатный Substack (или Buttondown до 100 подписчиков) → вставь реальный URL в `meta.newsletter_url` → build → push. Настрой welcome-письмо: «что это, почему полезно, архив изменений».
5. **Аналитика** (10 мин): бесплатный аккаунт goatcounter.com → раскомментируй строку внизу index.html и в scripts/build.py (PAGE_TMPL) → build → push.
6. **Google Search Console** (15 мин): добавь сайт, отправь sitemap.xml, запроси индексацию главной и 3–5 страниц инструментов.
7. **GitHub Sponsors** (15 мин, опционально): включи Sponsors на аккаунте — это твой донат-канал без комиссий.
8. **Запуск** (см. README, раздел Launch checklist): пост «The Free Tier Graveyard» на dev.to → r/webdev → Show HN. Вторник–четверг, утро по US. Один день сидишь в комментариях — это самое важное вложение времени за весь проект.

## Финансовая модель (прогноз, не обещание)

Расходы: 0 €/мес обязательных. Опционально домен ~10 €/год (сильно помогает доверию и SEO).

Здесь «платящий клиент» = спонсор или донатер, а подписчики рассылки — актив, который их приводит. Ставки — типичные для дев-рассылок, твои могут отличаться.

**Сценарий A — скромный старт** (~3–6 мес): 300–1000 подписчиков, 5–10 донатеров по 3–5 €/мес → **15–50 €/мес**. Трафик 3–10k визитов/мес с SEO.
**Сценарий B — рабочая машина** (~6–18 мес): 2–5k подписчиков, 1–2 спонсорских слота в рассылке по 50–150 € за выпуск (4 выпуска/мес) + донаты → **250–800 €/мес**.
**Сценарий C — заметный нишевый медиа-актив**: 15–30k подписчиков, постоянный спонсор сайта (300–800 €/мес) + слоты в рассылке + партнёрки инструментов из каталога → **1500–5000 €/мес**. На этом уровне такие активы также продаются целиком (обычно за 30–40 месячных прибылей).

Главный KPI: €/час твоего ручного труда. Модель построена так, что рост дохода почти не увеличивает трудозатраты — больше подписчиков ≠ больше работы, письма и сайт масштабируются бесплатно.

## Мониторинг и алерты (что и когда тебя побеспокоит)

Тебя дёргают только события, всё остальное молчит:

🚨 Изменилась pricing-страница → GitHub issue + email (понедельник)
🚨 Упал workflow → email от GitHub Actions автоматически
🚨 Ошибка в данных → issue от посетителя (шаблон в репозитории)
🚨 Всплеск/падение трафика → видно в GoatCounter (заходи раз в неделю, алертов не шлёт — это осознанно, чтобы не спамить тебя)

Сайт статический: нет базы, нет сервера, нет того, что может упасть ночью. GitHub Pages SLA — забота GitHub.

## Риски — честно

1. **SEO — это месяцы, не дни.** Первые 2–3 месяца трафик почти нулевой; всплески дают только Reddit/HN. Лекарство: качественный запуск + еженедельные поводы (изменения тарифов) для повторных постов.
2. **Конкуренты существуют** (free-for.dev — большой список на GitHub, freetiers.com и пр.). Наше отличие — верификация с датами, ловушки и «Кладбище», а не просто список ссылок. Отличие надо удерживать: протухшие даты убивают продукт.
3. **Провайдеры меняют страницы** так, что скрипт не видит текста (JS-рендеринг) — воркфлоу пометит это как ошибку fetch; такие инструменты проверяй руками раз в месяц.
4. **Монетизация требует аудитории.** До ~1000 подписчиков доход будет около нуля — это нормально и заложено в сценарий A.
5. **Юридически чисто**: только факты с публичных страниц, ссылки на источники, никакого скрейпинга закрытого контента, торговые марки упоминаются номинативно, партнёрки — только с пометкой. Не заявляй аффилиацию с провайдерами (дисклеймер уже в футере).

## План масштабирования (когда захочешь расти)

Строго по одному шагу за раз, каждый — только когда предыдущий работает:

1. 40–60 инструментов (по запросам из issues) → больше SEO-страниц.
2. Сравнительные страницы («Supabase vs Neon free tier») — build.py легко расширить, это самые конверсионные SEO-запросы.
3. Публичный JSON API (`data/tools.json` уже и есть API — просто задокументируй URL) → бэклинки от разработчиков.
4. Спонсорская страница /sponsor с ценами — когда рассылка >2k.
5. Автодрафты писем: скрипт может готовить черновик выпуска из diff'а изменений — твоя роль сведётся к «прочитал, нажал отправить».

- `sitemap.xml`, `robots.txt` — генерируются build.py
- `README.md` — деплой и чеклист запуска (по-английски, годится как публичный README репозитория)
